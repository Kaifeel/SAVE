# 게시물 상대 시간 표시 설계

## 목표

홈의 `방금 올라왔어요` 게시물과 게시물 상세 화면에 실제 작성 시각을 기준으로 한 상대 시간을 표시한다. 화면을 새로고침하지 않아도 시간이 자연스럽게 갱신되어야 한다.

## 표시 규칙

- 작성 후 1분 미만: `방금 전`
- 작성 후 1시간 미만: 경과한 분 단위로 `5분 전`
- 작성 후 24시간 미만: 경과한 시간 단위로 `2시간 전`
- 작성 후 24시간 이상: 경과한 날짜 단위로 `3일 전`
- 미래 시각은 클라이언트와 서버의 시계 차이로 간주하고 `방금 전`으로 표시한다.
- 작성 시각이 없거나 올바른 날짜로 해석되지 않으면 시간 문구를 표시하지 않는다.

## 데이터 흐름

백엔드의 물품 응답은 이미 `createdAt`을 제공한다. 프런트의 물품 정규화 단계에서 `created_at` 또는 `createdAt`을 읽어 정규화된 게시물의 `createdAt` 속성에 보존한다. API를 사용하지 않는 로컬 데이터와 새로 등록한 로컬 게시물에도 `createdAt`을 제공한다.

공용 상대 시간 포매터는 `createdAt`과 현재 시각을 받아 표시 문자열을 반환한다. 홈과 상세 화면은 동일한 포매터를 사용해 표시 규칙의 중복과 화면 간 불일치를 막는다.

## 자동 갱신

공용 훅이 현재 시각을 상태로 관리한다. 관련 화면이 마운트되어 있고 문서가 보이는 동안 60초 간격으로 현재 시각을 갱신한다. 브라우저 탭이 다시 보이는 시점에는 즉시 갱신한다. 이 과정은 서버 API를 다시 호출하지 않고 클라이언트에서만 계산한다.

분 단위 표시이므로 최대 약 59초의 경계 지연을 허용한다. 초 단위 타이머는 사용하지 않는다.

## 화면 변경

홈의 `방금 올라왔어요` 목록에서 현재 고정된 `방금 전` 문구를 게시물별 상대 시간으로 교체한다.

게시물 상세 화면에서는 제목과 위치·평점 정보 근처에 동일한 상대 시간을 표시한다. 작성 시각이 유효하지 않으면 시간 요소 자체를 렌더링하지 않아 불완전한 문구가 노출되지 않게 한다.

## 오류 및 경계 처리

날짜 파싱 실패는 예외를 발생시키지 않고 빈 문자열로 처리한다. 서버와 클라이언트 시간대가 달라도 ISO 날짜 문자열을 브라우저의 `Date`로 해석한 뒤 경과 시간을 계산한다. 백엔드가 시간대 정보 없는 `LocalDateTime` 문자열을 보내는 현재 계약은 기존 클라이언트 날짜 처리 방식과 동일하게 로컬 시각으로 해석한다.

## 테스트

- 상대 시간 포매터가 `방금 전`, 분, 시간, 일 단위를 올바르게 반환하는지 검증한다.
- 미래 시각, 누락 값, 잘못된 날짜를 검증한다.
- 물품 정규화가 API의 `createdAt`과 `created_at`을 보존하는지 검증한다.
- 홈의 최근 게시물이 고정 문구가 아닌 계산된 상대 시간을 표시하는지 검증한다.
- 게시물 상세 화면이 작성 상대 시간을 표시하고, 작성 시각이 없으면 생략하는지 검증한다.
- 가짜 타이머로 1분 경과 및 탭 재활성화 시 표시가 갱신되는지 검증한다.

## 범위 제외

검색 목록, 인기 게시물, 추천 게시물의 시간 표시는 이번 변경에 포함하지 않는다. 서버 API 형식과 데이터베이스 스키마도 변경하지 않는다.
