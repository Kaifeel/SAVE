# Expo Realtime Chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Expo chat placeholder with real chat-room, message, pagination, optimistic-send, read, and realtime behavior using the shared backend.

**Architecture:** Add a runtime-validated Expo chat API and a focused Zustand store. REST remains authoritative for writes and initial snapshots; a small STOMP adapter supplies room, chat-list, and notification updates and reconnects from the current access token.

**Tech Stack:** Expo SDK 57, Expo Router, React Native 0.86, Zustand 5, @stomp/stompjs 7, Jest Expo

**Spec:** `docs/superpowers/specs/2026-08-23-platform-integration-chat-push-design.md`

## Global Constraints

- Execute after the source-integration and STOMP reliability plans.
- Use only real API data; do not introduce chat fixtures or fabricated fallback metadata.
- Keep platform code Android/iOS compatible and runnable in iPhone Expo Go.
- Keep message writes on REST and realtime delivery on STOMP.
- Every response is runtime-validated before entering state.
