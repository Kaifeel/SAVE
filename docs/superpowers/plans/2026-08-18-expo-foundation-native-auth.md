# Expo Foundation and Native Authentication Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce a runnable canonical Expo Router app with validated runtime configuration, native email/Google authentication, rotating SecureStore sessions, and protected tab/stack navigation against the existing Spring backend.

**Architecture:** Create `apps/save-app` as a clean Expo application and keep the web client unchanged. Extend the existing backend with `/api/v1/auth/mobile/*` endpoints that return rotating refresh tokens in JSON, then consume those endpoints through a typed mobile API client and a small Zustand authentication store. Major screens use Expo Router; transient form state stays local.

**Tech Stack:** Expo SDK 57 scaffold from `create-expo-app`, Expo Router, React Native, TypeScript, Zustand, Expo SecureStore, Expo AuthSession, Jest/Jest Expo, React Native Testing Library, Spring Boot 3.3, JUnit 5, MockMvc.

**Spec:** `docs/superpowers/specs/2026-08-18-expo-src-parity-design.md`

## Global Constraints

- The canonical mobile app path is `apps/save-app` on branch `feature/expo-src-parity`.
- `src/` remains the web UI and behavior reference; do not copy downloaded mobile directories wholesale.
- Use the existing Spring backend, database, and API server; do not create a second backend.
- Do not add TanStack Query in this plan.
- Keep the access token in memory and the rotating refresh token in Expo SecureStore.
- Production bootstrap must reject missing API/OAuth configuration and any enabled mock mode.
- Do not render demo data after an API error or empty response.
- Never log access tokens, refresh tokens, Google ID tokens, or authorization codes.
- Each task follows RED, GREEN, REFACTOR and ends with a focused commit.

- [ ] **Step 4: Implement DTOs and controller**

Use these records:

```java
public record MobileRefreshRequest(@NotBlank String refreshToken) {}

public record MobileAuthResponse(
        String accessToken,
        String tokenType,
        boolean isNewUser,
        AuthUserResponse user,
        String refreshToken,
        Instant refreshTokenExpiresAt) {
    static MobileAuthResponse from(AuthSession session) {
        AuthResponse response = session.response();
        return new MobileAuthResponse(response.accessToken(), response.tokenType(),
                response.isNewUser(), response.user(), session.refreshToken(), session.expiresAt());
    }
}
```

Implement `MobileAuthController` at `/api/v1/auth/mobile`. `signup`, `login`, and `google` call `authSessionService.start(...)`; `refresh` calls `authSessionService.refresh(request.refreshToken())`; `logout` calls `authSessionService.logout(request.refreshToken())`.
